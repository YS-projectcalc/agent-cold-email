ColdStart (`~/dev/coldstart/`) canonical living docs, per its `CLAUDE.md`: `README.md` (per level), `SPEC.md` (architecture), `ROADMAP.md` (build order/status — now the ledger under the ROADMAP Contract, see below), `ARCHITECTURE.md`, `HANDOFF.md` (resume-here state), `MEMORY.md` (repo build lessons), `ACTIVATION.md` (owner go-live checklist, once created). NEVER create new status/audit/critique/handoff-vN docs. One exception: adversarial panel verdicts are frozen records under `docs/adversarial/panel-NN/` (allowed — not living docs, don't route new content there). Research/decision provenance also gets frozen dated files under `docs/research/*-YYYY-MM-DD.md` — these are write-once, never edited after landing (even to fix a noted error — corrections get a pointer note elsewhere, e.g. ROADMAP, not an edit to the frozen file).

**ROADMAP Contract adopted 2026-07-13** (from the global `~/CLAUDE.md` § ROADMAP Contract, now live in this repo): ROADMAP.md keeps exactly TWO living sections, `## Now` (≤5 items, actively worked) and `## Open` (everything else, one line each: `- [ ] YYYY-MM-DD [ORDER|ASK|IDEA] <item>`, status tags like `[gated:founder]`/`[dark-unarmed]`). The OLD narrative "Session log" section is GONE from ROADMAP.md — it was migrated verbatim to `archive/ROADMAP-done.md` (append-only, dated; see `archive/INDEX.md` for pointers) as part of a 2026-07-13 `/handoff` restructure. New completed work no longer gets a narrative paragraph — it gets checked `- [x]` lines in `## Open` with a compact evidence pointer (commit hash, test count, verdict), and self-drains to the archive at the NEXT handoff. Do not re-add a narrative session-log section — that would be exactly the sprawl this Contract exists to kill. HANDOFF.md's "Where we are right now" is a snapshot (facts), "In flight / next" is action-oriented (what's running/blocked/next); "Resume" section is the founder-facing script — a bookkeeping brief that says "surgical edits to those sections only" should NOT touch Landmines/Key files even if related content would fit, unless explicitly told to.

Git in this repo: routinely a shared/live worktree across concurrent agent sessions (see ROADMAP-done.md archive, 07-09 note re: a concurrent `git add -A` sweeping up in-progress files) — historically bookkeeper briefs here were git-read-only, but a 2026-07-13 brief explicitly asked for a docs-only commit on main (message prefix "docs:") — commit when the brief says so, stay read-only otherwise. Watch for concurrent edits to ROADMAP.md/HANDOFF.md mid-session (hit once 2026-07-13 — Edit failed with "file modified since read," re-Read caught a sibling process's in-flight restructure).

**Concatenated-bullet gotcha (2026-07-19):** a live `ROADMAP.md ## Open` bullet can hold TWO unrelated concerns sharing one `- [ ]` checkbox — a newly-found defect narrative gets PREPENDED onto an older, still-unresolved item's line instead of getting its own bullet (found: a 2026-07-19 gmail_api wire-Message-ID paragraph prepended onto a 2026-07-16 ChatGPT/Claude-indexing paragraph, both under one checkbox dated 2026-07-19). Don't blindly check off / archive the whole line just because the brief names the newer concern as closed — read the full bullet, split it: archive the closed concern with its own evidence, leave the unrelated still-open concern as its own clean bullet (re-date it to match its OWN internal timestamps, not the line's stale date tag, since the tag got overwritten when the prepend happened). **Exact-match Edit fails silently on dense entries even with byte-identical text (2026-08-05):** the `Edit` tool's old_string match failed on a huge ROADMAP.md `## Open` bullet even after re-reading the exact text and `xxd`-diffing it byte-for-byte against my old_string (no encoding mismatch found — root cause never isolated, likely a length/normalization quirk in the tool on very long single-line old_strings with many `·`/curly-quote/emoji characters). Fix: splice by 0-indexed line number via a Python heredoc (`lines[23:25] = [new_text]`) instead of fighting Edit's exact-match on dense paragraph-bullets — reliable, and lets me stash the replaced text to a scratchpad file for the archive-append step in the same pass. Use this pattern any time a ROADMAP.md/HANDOFF.md bullet is a single dense multi-hundred-word paragraph (the norm in this repo) rather than short lines. [[coldstart-doc-convention-map]]

**Restructure-not-delete pattern for a superseded dense bullet (2026-08-05):** when a brief says "restructure X into Y" and Y's given text doesn't cover every sub-item X held (a class-sweep inventory got refined and several deferred sub-items weren't re-mentioned), don't let the uncovered items silently vanish — (1) snapshot the ORIGINAL bullet verbatim into today's `archive/YYYY-MM-DD-<slug>/superseded-<doc>-<section>.md`, (2) write the brief's new content as given, (3) add one more `- [ ]` bullet carrying forward every uncovered sub-item verbatim (tag it "deferred, not yet re-triaged," point at the archive file for full provenance), (4) add an `archive/INDEX.md` pointer line for the new archive file. This keeps "archive, never delete" honest even when a brief's replacement text is a genuine narrowing, not a full 1:1 supersession. [[coldstart-doc-convention-map]]

**Verify a frozen doc's own claims against each other before trusting either (2026-08-05):** two same-day frozen adversarial docs disagreed — `audit-dunning-2026-08-05.md` found the cron trigger "ARMED and LIVE" while `forward-path-audit-2026-08-05.md`'s L8 claimed "the cron is commented out in wrangler.toml." Direct `grep`/`Read` of `wrangler.toml` + `scheduled.ts` + `index.ts` confirmed audit-dunning was right and forward-path-audit's L8 was wrong (it trusted a stale source-code comment instead of checking the actual trigger config) — `reconcileMailboxCredentialPushes` was also already cron-wired (inside the deliverability leg), a second L8 sub-claim that was also false. Frozen docs are write-once and NOT to be edited after the fact, but a bookkeeping brief that repeats a frozen doc's specific checkable claim still needs that claim independently verified before landing in a living doc (ROADMAP/HANDOFF) — write the corrected finding into the living doc, not the frozen doc, and flag the discrepancy in the manifest. **Split-ownership file technique (2026-07-14):** ACTIVATION.md is a canonical doc I'm allowed to touch, but it can arrive with an ALREADY-DIRTY working tree from a different lane (e.g. a builder had drafted a whole Gate-2 engine runbook, uncommitted, adjacent to the one line my brief authorized). `git checkout`/`stash` risks losing their in-flight text; committing the whole file risks landing content the brief explicitly said isn't ready. Fix: make my Edit directly on the live (dirty) file, then hand-build a minimal patch — `git diff -U0 -- FILE > full.patch`, mechanically extract (via `sed`, never retyped by hand — Unicode em-dashes/arrows in this repo's prose break hand-transcribed patches) just my target line plus ~3-4 lines of real surrounding context on each side (a 1-2 line minimal hunk reliably fails `git apply --check` with "patch does not apply" even when content matches byte-for-byte — use the full original hunk's context window), then `git apply --cached --check` then `--cached` (no working-tree flag) to stage ONLY that hunk into the index. `git diff --cached` afterward should show just my line; `git diff` (unstaged) should show just their untouched content. Commit, then `git status` confirms their hunk is still sitting dirty exactly as before. [[coldstart-doc-convention-map]]
