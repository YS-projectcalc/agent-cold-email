ColdStart (`~/dev/coldstart/`) canonical living docs, per its `CLAUDE.md`: `README.md` (per level), `SPEC.md` (architecture), `ROADMAP.md` (build order/status — now the ledger under the ROADMAP Contract, see below), `ARCHITECTURE.md`, `HANDOFF.md` (resume-here state), `MEMORY.md` (repo build lessons), `ACTIVATION.md` (owner go-live checklist, once created). NEVER create new status/audit/critique/handoff-vN docs. One exception: adversarial panel verdicts are frozen records under `docs/adversarial/panel-NN/` (allowed — not living docs, don't route new content there). Research/decision provenance also gets frozen dated files under `docs/research/*-YYYY-MM-DD.md` — these are write-once, never edited after landing (even to fix a noted error — corrections get a pointer note elsewhere, e.g. ROADMAP, not an edit to the frozen file).

**ROADMAP Contract adopted 2026-07-13** (from the global `~/CLAUDE.md` § ROADMAP Contract, now live in this repo): ROADMAP.md keeps exactly TWO living sections, `## Now` (≤5 items, actively worked) and `## Open` (everything else, one line each: `- [ ] YYYY-MM-DD [ORDER|ASK|IDEA] <item>`, status tags like `[gated:founder]`/`[dark-unarmed]`). The OLD narrative "Session log" section is GONE from ROADMAP.md — it was migrated verbatim to `archive/ROADMAP-done.md` (append-only, dated; see `archive/INDEX.md` for pointers) as part of a 2026-07-13 `/handoff` restructure. New completed work no longer gets a narrative paragraph — it gets checked `- [x]` lines in `## Open` with a compact evidence pointer (commit hash, test count, verdict), and self-drains to the archive at the NEXT handoff. Do not re-add a narrative session-log section — that would be exactly the sprawl this Contract exists to kill. HANDOFF.md's "Where we are right now" is a snapshot (facts), "In flight / next" is action-oriented (what's running/blocked/next); "Resume" section is the founder-facing script — a bookkeeping brief that says "surgical edits to those sections only" should NOT touch Landmines/Key files even if related content would fit, unless explicitly told to.

Git in this repo: routinely a shared/live worktree across concurrent agent sessions (see ROADMAP-done.md archive, 07-09 note re: a concurrent `git add -A` sweeping up in-progress files) — historically bookkeeper briefs here were git-read-only, but a 2026-07-13 brief explicitly asked for a docs-only commit on main (message prefix "docs:") — commit when the brief says so, stay read-only otherwise. Watch for concurrent edits to ROADMAP.md/HANDOFF.md mid-session (hit once 2026-07-13 — Edit failed with "file modified since read," re-Read caught a sibling process's in-flight restructure).

**Concatenated-bullet gotcha (2026-07-19):** a live `ROADMAP.md ## Open` bullet can hold TWO unrelated concerns sharing one `- [ ]` checkbox — a newly-found defect narrative gets PREPENDED onto an older, still-unresolved item's line instead of getting its own bullet (found: a 2026-07-19 gmail_api wire-Message-ID paragraph prepended onto a 2026-07-16 ChatGPT/Claude-indexing paragraph, both under one checkbox dated 2026-07-19). Don't blindly check off / archive the whole line just because the brief names the newer concern as closed — read the full bullet, split it: archive the closed concern with its own evidence, leave the unrelated still-open concern as its own clean bullet (re-date it to match its OWN internal timestamps, not the line's stale date tag, since the tag got overwritten when the prepend happened). **Exact-match Edit fails silently on dense entries even with byte-identical text (2026-08-05):** the `Edit` tool's old_string match failed on a huge ROADMAP.md `## Open` bullet even after re-reading the exact text and `xxd`-diffing it byte-for-byte against my old_string (no encoding mismatch found — root cause never isolated, likely a length/normalization quirk in the tool on very long single-line old_strings with many `·`/curly-quote/emoji characters). Fix: splice by 0-indexed line number via a Python heredoc (`lines[23:25] = [new_text]`) instead of fighting Edit's exact-match on dense paragraph-bullets — reliable, and lets me stash the replaced text to a scratchpad file for the archive-append step in the same pass. Use this pattern any time a ROADMAP.md/HANDOFF.md bullet is a single dense multi-hundred-word paragraph (the norm in this repo) rather than short lines. [[coldstart-doc-convention-map]]

**Restructure-not-delete pattern for a superseded dense bullet (2026-08-05):** when a brief says "restructure X into Y" and Y's given text doesn't cover every sub-item X held (a class-sweep inventory got refined and several deferred sub-items weren't re-mentioned), don't let the uncovered items silently vanish — (1) snapshot the ORIGINAL bullet verbatim into today's `archive/YYYY-MM-DD-<slug>/superseded-<doc>-<section>.md`, (2) write the brief's new content as given, (3) add one more `- [ ]` bullet carrying forward every uncovered sub-item verbatim (tag it "deferred, not yet re-triaged," point at the archive file for full provenance), (4) add an `archive/INDEX.md` pointer line for the new archive file. This keeps "archive, never delete" honest even when a brief's replacement text is a genuine narrowing, not a full 1:1 supersession. [[coldstart-doc-convention-map]]

**Verify a frozen doc's own claims against each other before trusting either (2026-08-05):** two same-day frozen adversarial docs disagreed — `audit-dunning-2026-08-05.md` found the cron trigger "ARMED and LIVE" while `forward-path-audit-2026-08-05.md`'s L8 claimed "the cron is commented out in wrangler.toml." Direct `grep`/`Read` of `wrangler.toml` + `scheduled.ts` + `index.ts` confirmed audit-dunning was right and forward-path-audit's L8 was wrong (it trusted a stale source-code comment instead of checking the actual trigger config) — `reconcileMailboxCredentialPushes` was also already cron-wired (inside the deliverability leg), a second L8 sub-claim that was also false. Frozen docs are write-once and NOT to be edited after the fact, but a bookkeeping brief that repeats a frozen doc's specific checkable claim still needs that claim independently verified before landing in a living doc (ROADMAP/HANDOFF) — write the corrected finding into the living doc, not the frozen doc, and flag the discrepancy in the manifest. [[coldstart-doc-convention-map]]

**Frozen adversary docs can land in the wrong worktree, not just the wrong sub-`.claude/` (2026-08-06):** `docs/adversarial/audit-stripe-webhook-2026-08-06.md` (a full-boundary-audit verdict cited by a bookkeeping brief) existed only as an UNTRACKED file in the `main` worktree (`~/dev/coldstart`), not in the integration worktree/branch the brief was folding it into (`~/dev/coldstart-wt-integration2`, `integrate/2026-08-06-wave2`) and not in any of the six lane worktrees either — the fix lane (`fix/stripe-webhook-p0`) that closed the doc's findings never carried the doc itself along. When a brief cites a frozen `docs/adversarial/*` path, `find` across ALL live worktrees (not just cwd) before treating it as missing — it's often sitting real but orphaned in a sibling worktree, uncommitted. Flag the orphan location in the manifest rather than silently reading it from wherever it happened to be found. [[coldstart-doc-convention-map]]

**Stray duplicate agent-memory location (2026-08-05, unresolved):** `apps/platform/src/.claude/agent-memory/class-sweeper/` holds untracked, NEW class-sweeper memory files (incl. `vendor-identity-leak-surfaces.md`, not present at the canonical root `.claude/agent-memory/class-sweeper/`) — some sub-agent ran with cwd = `apps/platform/src` instead of the repo root and wrote memory to the wrong nested `.claude/`. A brief that says "leave `apps/platform` uncommitted, don't touch the source" also covers this path even though it's memory, not source — left untouched this pass; flagged for the orchestrator to decide whether to relocate/merge it into the canonical root location before it's lost to a future `git clean`. [[coldstart-doc-convention-map]]

**Concatenated-bullet split extends to "mostly done" ROADMAP entries too (2026-08-06):** a brief said "check off X, all landed" for a 4-sub-item `## Open` bullet that also carried one unrelated "Separate residual" sentence the brief never mentioned. Checking the whole line `[x]` would have silently closed that residual too. Fix (same family as the 2026-07-19 gotcha): check the bullet off with the brief's evidence, but SPLIT the unconfirmed sub-item into its own fresh `- [ ]` bullet immediately after, carrying its original text verbatim, tagged "status not independently confirmed this pass." Cheap and keeps the checked box honest. [[coldstart-doc-convention-map]]

**HANDOFF "Where we are" superseding-paragraph convention is load-bearing, not just style (2026-08-06):** this doc's own convention — prepend a new dated/emoji-tagged paragraph that says in its own first clause "(supersedes the 🟡/🔴/etc. paragraph below)" — means a bookkeeper doing a "full refresh" doesn't need to delete or rewrite older paragraphs; prepending one new paragraph is enough and matches house style exactly (grep the file for existing `supersedes` clauses before inventing a different pattern). Landmines bullets follow a DIFFERENT convention (no history preservation — a stale landmine bullet gets edited in place to current truth, since a landmine is a live warning, not a timestamped log entry) — don't apply the "prepend, don't rewrite" pattern there.

**A brief's explicit Landmines edit-list can miss bullets that are stale for reasons OUTSIDE its own diff (2026-08-06):** a brief named 3 specific Landmines bullets to fix (tied to the wave it was reporting) but two OTHER bullets (dunning-cron-pending-gate, msgchannel-Inc1-pending-gate) were already stale from a PRIOR wave that had shipped days earlier — leaving them would have had the doc contradict its own "Where we are" paragraph one section up. Fix: when "full refresh authorized" language is present, cross-check every Landmines bullet against the doc's OWN already-recorded facts (not new claims) before leaving it untouched, and fix any that are self-contradictory even if the brief didn't name them — flag the expansion in the manifest as "beyond literal brief enumeration, backed by the doc's own facts."

**"Rewrite" language implies a snapshot even when the brief doesn't ask for one (2026-08-18):** a brief said "rewrite 'Where we are' + 'In flight/next' + 'Resume' to the post-ship state" — a real churn of multiple HANDOFF.md sections, not the landmine-only "edit stale bullets in place" pattern. Even though the brief didn't explicitly ask for an archive snapshot, I pulled the pre-edit file via `git show HEAD:HANDOFF.md` and archived it to a new dated `archive/YYYY-MM-DD-<slug>/prior-HANDOFF.md` + `INDEX.md` pointer before editing, matching every prior full-refresh HANDOFF session in this repo's own history. Rule of thumb: "surgical edit to section X" → no snapshot needed (Landmines/Key-files convention). "Rewrite section(s) to the post-<milestone> state" spanning "Where we are"/"In flight"/"Resume" together → snapshot first, same as a `/handoff` restructure. [[coldstart-doc-convention-map]]

**A brief's own enumerated section list can still get mis-scanned mid-task — recheck it before calling done (2026-08-18):** a brief named three HANDOFF sections to rewrite in one sentence ("Where we are right now" + "In flight / next" + "Resume") but I initially only executed the first two, having skimmed the sentence as a two-item list. Caught it only by re-reading the original brief text verbatim before reporting back, not by any tooling. Before sending the final manifest, diff the brief's literal instruction list against what was actually edited — don't rely on a mental summary of "what the brief asked for."

**`wrangler deployments list`/`wrangler pages deployment list` need explicit `--name`/project flags in this repo (2026-08-18):** running either from repo root (rather than `apps/platform/`) or without `--project-name` errors out ("You need to provide a name for your Worker" / "Project not found") even though `wrangler.toml` exists at `apps/platform/wrangler.toml` — this repo's multi-workspace layout means wrangler can't infer the target from cwd alone. Verifying a claimed Worker/Pages deploy hash without those flags fails silently into an error, not a false pass — but don't skip verification on that error alone; fall back to live `/status` + a byte-diff of a known deployed artifact (e.g. `openapi.yaml`) as an equally strong substitute proof.

**"Mark done + point next lane" briefs need a fresh checked bullet, not a retrofit of the giant narrative one (2026-08-19):** a wave-close brief said "mark the customer-continuity entries DONE" against a single 2026-08-18 `## Open` bullet that had grown to ~5000 words across a design phase + build phase + an UNRELATED still-open arm-gate blocker mentioned inside it. Checking that whole line `[x]` would have silently closed the unrelated blocker too (the 2026-07-19/08-06 concatenated-bullet gotchas, but at giant-narrative scale). Fix: append a SHORT "BUILD COMPLETE, see the fresh entry below" pointer to the giant `- [ ]` line (leaving it unchecked, since the arm-gate blocker inside it is still real) and add a genuinely NEW `- [x]` bullet carrying the actual evidence. Also: a `## Now` section that's gone stale (items from weeks ago, never triaged into `## Open`, several still carrying live open sub-asks inside their prose) is NOT safe to bulk-archive on an "update `## Now`" instruction alone — several of ColdStart's 2026-07-28-era `## Now` items had undone sub-items buried in their prose; the safe move was to prepend the new active item and flag the stale backlog for a real triage pass rather than silently deciding those old items were done. [[coldstart-doc-convention-map]]

**Gate docs can hand you near-verbatim ROADMAP lines, and a fix commit can cross-reference a ROADMAP item that doesn't exist yet (2026-08-19):** an adversary gate's "Recommended follow-ups (ROADMAP, not gates)" section supplied literal `- [ ] YYYY-MM-DD [TAG] ...` text — use it (attributed), don't re-paraphrase from scratch. Separately, a same-day cleanup commit's new code comment read "tracked on the ROADMAP re-buy item" for an item that, on checking, did NOT yet exist in ROADMAP.md (the gate's own recommendation to fold it into "the existing r3 ROADMAP item" was itself referring to something never actually landed) — grep for the claimed cross-ref before trusting it; when it's missing, this is exactly the kind of gap a bookkeeping pass exists to backfill, not a discrepancy to flag-and-skip.

**Mechanical index-file compaction: budget 3-4x more cutting than intuition suggests, and verify by re-measuring after each pass (2026-08-19):** asked to compact a 90-line, one-clause-per-entry memory index from 20.2KB to under 17.1KB, a first pass of "tighten word choice, keep the same two clauses per entry" on the 33 longest lines cut only ~250 bytes of ~3900 needed — nearly a no-op, because swapping words for shorter synonyms while keeping both the "what" and "how to fix" clauses barely moves total bytes. What worked: cut every entry down to ONE clause (usually the "what happens" mechanism, since that's what search/recall keys on; drop the "how to fix" clause entirely when the slug + linked file already carries it), re-measure with `wc -c` after each batch, and expect to need 2-3 batches (widening which lines you touch each time) before hitting a hard byte target — don't assume one aggressive-feeling pass is enough; check the number.

**Repo-root `MEMORY.md` has no topic sections — it's one flat chronological bullet list under the H1, with occasional dated `## YYYY-MM-DD ...` milestone-wave headers interspersed (2026-08-23 checked: only 2 H2s exist, `## 2026-07-28 standing lessons` and `## 2026-08-05 incident + hotfix`; everything else, including all deploy/vendor/infra gotchas, is a flat dated bullet before the first H2).** A brief that says "append to whatever section holds deploy/vendor gotchas" has no such section to find — insert the new dated bullet chronologically among the flat bullets (find the two existing bullets whose dates bracket the new one, insert between them) rather than tacking it onto the end of the file; that's what every existing gotcha bullet in this file already does and keeps the loose date-ordering intact. [[coldstart-doc-convention-map]]

**Bulk `## Open` prune-and-archive passes (2026-08-23, 108-line removal + 2 edits across a 231-item/260-line file): do the whole edit in ONE atomic script pass over an in-memory line array, not sequential `Edit` calls.** Read the untouched file once into a 0-indexed line list, resolve every target row by ORIGINAL 1-based line number looked up against that single untouched read (never against a file you've already started mutating — line numbers shift), build the new content by iterating that array once (skip-if-removed / rewrite-if-edited / keep-otherwise), then write the result in one shot. Verification that scales past ~10 items: don't diff by line number (it shifts) — for every DONE/DROP row, confirm its ORIGINAL full line text (fetched by line number from the untouched read) is ABSENT from the new file; for every unmodified KEEP row, confirm its original full line text is byte-identical PRESENT in the new file (`orig_line in new_content`, full-set, not a random sample) — this catches both "deleted something it shouldn't have" and "kept something it shouldn't have" with one substring-membership check per row, cheap even at 100+ rows. Counts self-check: `before_count − DONE − DROP + (new lines added) == after_count`, verified with `grep -c` before AND after. [[coldstart-doc-convention-map]]

**Conditional briefed verdicts recur — resolve them for real, don't force-fit the orchestrator's assumed outcome (2026-08-23, twice in one 2-pass ROADMAP cleanup).** A brief sometimes gives a verdict gated on a check IT names but hasn't itself run against the current state (pass 1: "DONE only if `grep -ci "early access" ... ` returns 0, else KEEP unchanged"; pass 2: "DONE if the line's own text says shipped, if it lists an unbuilt increment, KEEP and tell me which"). Both times the brief's own arithmetic/expectation assumed the DONE branch; both times I ran the actual check (a live grep; reading the target line's own tail) and one came back DONE, the other came back KEEP because the line itself said an increment was still unbuilt. Execute whichever branch the check actually lands on, recompute any brief-supplied totals from that (don't silently keep their assumed count), and name the deviation explicitly in the report rather than either overriding the brief's arithmetic silently or forcing the outcome the brief seemed to expect. [[coldstart-doc-convention-map]]

**A giant multi-sub-item bullet marked DONE by the brief still needs the concatenated-bullet gotcha applied, but the tracked-elsewhere pattern can make a full checkbox honest (2026-08-23).** The 2026-07-14 "Design-lane FULL page brief" bullet named ~12 sub-items; the brief's DONE ruling cited file-existence evidence for only 3 of them. Rather than assume the rest were unconfirmed (which would call for the usual split-the-bullet treatment), I ran `ls site/*.html` myself and found ALL the remaining static-page sub-items already existed as real files; the 2 sub-items that weren't pages (dashboard billing UI, a deliverability proof page) each already had their OWN separate still-open `## Open` line tracking them (one confirmed by grep, one riding a line being dropped in the same pass) — so checking the WHOLE original bullet `[x]` didn't silently close anything, because nothing inside it was uniquely-tracked-only-here and still open. Rule: before splitting a dense bullet on principle, check whether every one of its sub-items already has independent tracking elsewhere (or is independently verifiable) — if so, a full checkmark is honest; the split is for when a sub-item's ONLY record of being open lives inside the bullet you're about to close. [[coldstart-doc-convention-map]]

**"Disk still shows the old state" from the orchestrator can mean THEIR check hit a different worktree, not that your write failed (2026-08-23).** After committing a 2-file/4-file ROADMAP pass-2 edit exactly as briefed, the orchestrator reported "still shows 127 open, no Pass 2 sections" and asked me to re-execute. Before redoing (which would have double-applied removals against already-removed lines and corrupted the file), I re-ran the same verification greps AND `git log`/`git diff --stat` against the exact path I was told to use — confirmed already committed, working tree clean, counts correct — then ran `git worktree list`: this repo had 5 worktrees, only the one I was briefed to use was on `main`; the other 4 were on unrelated feature branches that had never merged the day's cleanup commits. Lesson: when told "disk doesn't show it" after you've verified a commit landed on the correct branch/path, don't assume your own tool calls lied — re-verify against the SAME path with `git log`+`git diff --stat` (empty diff = committed content is the working tree), then check `git worktree list` for a same-repo, different-branch mismatch on the requester's side before re-executing anything that mutates state. [[coldstart-doc-convention-map]]

**Split-ownership file technique (2026-07-14):** ACTIVATION.md is a canonical doc I'm allowed to touch, but it can arrive with an ALREADY-DIRTY working tree from a different lane (e.g. a builder had drafted a whole Gate-2 engine runbook, uncommitted, adjacent to the one line my brief authorized). `git checkout`/`stash` risks losing their in-flight text; committing the whole file risks landing content the brief explicitly said isn't ready. Fix: make my Edit directly on the live (dirty) file, then hand-build a minimal patch — `git diff -U0 -- FILE > full.patch`, mechanically extract (via `sed`, never retyped by hand — Unicode em-dashes/arrows in this repo's prose break hand-transcribed patches) just my target line plus ~3-4 lines of real surrounding context on each side (a 1-2 line minimal hunk reliably fails `git apply --check` with "patch does not apply" even when content matches byte-for-byte — use the full original hunk's context window), then `git apply --cached --check` then `--cached` (no working-tree flag) to stage ONLY that hunk into the index. `git diff --cached` afterward should show just my line; `git diff` (unstaged) should show just their untouched content. Commit, then `git status` confirms their hunk is still sitting dirty exactly as before. [[coldstart-doc-convention-map]]
